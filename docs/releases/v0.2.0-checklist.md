# Monitor Hub v0.2.0 Desktop Shipping Checklist

Status legend:

- `[x]` verified for this release;
- `[ ]` still requires explicit/manual verification;
- `[N/A]` not enabled or no release credential is available.

## Identity
- [x] Canonical product name is Monitor Hub
- [x] Executable/window/taskbar icon is packaged
- [x] System-tray icon is provided by the desktop application
- [ ] Manually inspect 16/24/32 px icon rendering on a real Windows desktop
- [x] Version/build identity is present in desktop diagnostics; v0.2.0 release will bind it to root VERSION

## Lifecycle
- [x] Single-instance guard/activation implementation is integrated
- [x] Close-to-tray vs explicit Quit semantics are implemented and documented
- [x] Owned background control process is stopped/terminated during explicit Quit
- [x] Background monitoring is not coupled to the lifetime of the visible main window
- [ ] Manual sleep/wake behavior check on the final installed build
- [ ] Manual multi-monitor/off-screen restore check on the final installed build

## Background and startup
- [x] Tray menu exposes high-value desktop actions and status
- [x] Important attention/completion/control failures can raise desktop notifications
- [x] Launch-at-login is opt-in
- [x] Development checkouts are blocked from registering transient build paths for startup
- [x] Background control is policy-bounded and can be disabled in Settings

## User data and diagnostics
- [x] Project/workspace data lives outside managed install payload
- [x] Uninstall does not intentionally remove external project/workspace data
- [x] Copy diagnostics is available from the desktop UI
- [x] Claude status bridge allow-lists metadata and does not persist OAuth/API keys/prompts/tool payloads
- [ ] Log rotation/bounded-log policy should be audited separately before claiming full log-lifecycle coverage

## Windows UX
- [x] Unicode build flags and Chinese UI paths are exercised in CI/source configuration
- [x] Installer is per-user and does not require elevation
- [x] Start Menu shortcut and uninstall registration are created
- [ ] Manual high-DPI checks at 125%, 150%, 200%
- [ ] Manual keyboard tab-order/accessibility pass

## Distribution
- [x] Installer/package generated from CI
- [x] Portable, installer and updater payload derive from one staged install tree
- [x] Qt and MSVC runtime are app-local
- [x] Update manifest contains per-file size + SHA-256
- [x] Updater archive has SHA-256
- [x] Stable release publishes SHA256SUMS.txt for user-facing assets
- [x] Installed-package diagnostics + silent uninstall smoke are automated
- [N/A] Authenticode code signing: no signing identity is configured in the repository release pipeline
- [ ] End-to-end automatic apply/rollback of a live installed update is not claimed as verified by v0.2.0 release CI

- [x] Silent installer smoke into a clean temporary install directory
- [x] Installed executable diagnostics smoke
- [x] Silent uninstall smoke
- [ ] Manual first-launch visual check of final v0.2.0 installer

## Release decision

Automated release blockers are required to be green before publishing.

The unchecked manual-polish items above are tracked transparently and must not be represented as already tested. They do not change the core package integrity, authority model, or install/uninstall safety guarantees validated by CI.
