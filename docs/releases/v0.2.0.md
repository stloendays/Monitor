# Monitor Hub 0.2.0

Monitor Hub 0.2.0 is the first integrated Windows desktop release of the current C++/Qt control plane.

It combines monitoring visibility, Agent activity, policy-bounded recovery, durable main-Agent notifications, Claude Code integration, and a release-managed Windows desktop lifecycle in one installable application.

## 推荐下载 / Recommended download

### 第一次安装

1. 下载 **`Monitor-Hub-0.2.0-win64-setup.exe`**。
2. 双击安装，建议保留默认目录：
   `%LOCALAPPDATA%\Programs\Monitor Hub`
3. 安装结束后勾选 **“安装完成后启动 Monitor Hub”**。
4. 首次启动后检查：
   - 监控项目/工作目录；
   - Claude CLI / statusLine 接入；
   - 通知设置；
   - 自动处理是否启用；
   - 项目的 recovery policy 与允许的 L1/L2 动作。
5. 如果你希望 Monitor Hub 随 Windows 启动，请在应用设置中主动开启；安装器不会偷偷开启开机启动。

> 当前 Windows 构建尚未使用商业代码签名证书。Windows SmartScreen 可能显示“未知发布者”。请只从本仓库的官方 GitHub Releases 下载，并使用 `SHA256SUMS.txt` 校验文件完整性。

## 0.2.0 重点变化

### Monitor / Agent 控制台

- Overview / Project / Task / Issue / Agent run / Raw evidence 分层下钻；
- Issue / Agent Event Timeline；
- Attention 视图与 durable notification outbox；
- 项目完成、恢复失败、需要主 Agent/用户决策时可以形成持久通知；
- 新建监控任务可通过 Setup Agent 办理，而不是手工编辑 registry JSON。

### Policy-bounded 自动处理

- L1：仅允许 recovery policy 明确授权的 deterministic handlers；
- L2：仅允许受约束的 child-Agent profile；
- L3：必须升级给主 Agent / 用户；
- command payload 不能自行选择 shell、可执行文件或越权 argv；
- 支持 read-only probe、本地 restart、PBS `qsub` restart；
- `task.restarted` / `agent.completed` **不等于** `issue.recovery_verified` / `issue.resolved`；
- 后台 control tick 会按固定顺序运行 dispatcher → worker → outbox，并保持幂等。

### Claude Code 集成

- Claude CLI 是否运行；
- 5 小时 / 7 天使用窗口与 reset 时间；
- 当前 session/workspace/worktree；
- 当前 Agent、最近工具、最近 Agent 调用元数据；
- Claude workspace 与 Monitor 项目路径自动关联；
- 原生 `monitor_hub_cli --claude-statusline`，正式安装版不依赖外部 Python 才能接 statusLine；
- bridge 只保存白名单元数据，不保存 OAuth/API key、prompt、对话正文、tool input/output。

### Windows 桌面产品化

- Qt 6 桌面 UI；
- GPT/Claude 风格现代界面；
- 托盘/后台运行；
- 单实例激活；
- 设置持久化；
- 可选开机启动；
- 桌面通知；
- Windows installer / portable package / updater package；
- app-local MSVC CRT；
- 安装后 diagnostics、卸载和 updater manifest/hash 都纳入 CI。

## 安全与数据边界

- 安装/卸载不会删除项目目录、计算结果或外部 workspace；
- 自动启动必须由用户主动开启；
- 开发目录含 `.git` 时不允许 release updater 自覆盖源码 checkout；
- 自动处理权限由 recovery policy 控制；
- L3 事项不会被后台 worker 自动越权处理；
- release/update package 使用 manifest + per-file SHA-256；
- updater 稳定资产名保持 `monitor-hub-windows-x64.zip`。

## 升级建议

如果你正在运行旧的 Python UI，可以并行安装 0.2.0 Qt 版本进行验证。正式安装版的可执行文件与用户数据/项目数据分离，不需要把已有计算目录复制进安装目录。

如果你在 Git clone 中开发，请继续使用 Git 工作流更新源码，不要用 Release updater 覆盖开发 checkout。
