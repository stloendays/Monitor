# Monitor Hub v0.2.0

Monitor Hub v0.2.0 is the first integrated desktop release built from the current C++/Qt control-plane stack.

> **Recommended download:** `Monitor-Hub-0.2.0-win64-setup.exe`  
> Windows 10/11 x64 · per-user installation · no administrator permission required.

## Which file should I download?

- **Most users:** `Monitor-Hub-0.2.0-win64-setup.exe`
- **Portable/manual use:** `Monitor-Hub-0.2.0-win64-portable.zip`
- **Automatic updater only:** `monitor-hub-windows-x64.zip`
- **Integrity verification:** `SHA256SUMS.txt`

The updater ZIP is not the recommended manual installation package.

## Automatic recovery and safety

The desktop control loop can process authorized recovery work in the background. It can be disabled in **Settings → 自动处理已授权的恢复任务（L1/L2）**.

Monitor Hub separates:

- **L1** deterministic/pre-authorized actions;
- **L2** bounded child-Agent work;
- **L3** main-Agent/user decisions.

An action finishing is not treated as proof that an issue is resolved. Recovery must be verified downstream before the issue lifecycle can advance to resolved.

Project monitors remain observers/recovery verifiers. They emit idempotent commands through the global control plane instead of directly executing arbitrary recovery. Executable/script/argv authority remains in the validated project recovery policy, not in runtime command payloads.

## Installation behavior

The Windows installer:

- installs for the current user;
- does not request administrator privileges;
- does not silently enable launch-at-login;
- creates a Start Menu shortcut;
- preserves project/workspace data outside the managed installation directory during uninstall.

See `docs/DOWNLOAD_AND_INSTALL.md` for the full install and first-run guide.

## Windows download warning

If Windows shows a SmartScreen/reputation prompt, verify that the file came from the official `stloendays/Monitor` GitHub Release and compare its SHA-256 against `SHA256SUMS.txt` before choosing to continue.

## Known release note

Code signing is not assumed by the build pipeline. A future signing identity can be added without changing the package/update contracts.
