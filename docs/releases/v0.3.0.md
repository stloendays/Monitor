# Monitor Hub 0.3.0

Monitor Hub 0.3.0 is the next stable desktop release after 0.2.1. It keeps the existing Windows installer, updater payload, Protocol v1 event contract, and recovery-authority model while substantially improving project Q&A, desktop resilience, workspace navigation, configuration recovery, and event inspection.

## Recommended download

| User | File | Notes |
|---|---|---|
| Windows user | `Monitor-Hub-0.3.0-win64-setup.exe` | Recommended installer. Per-user install, no administrator rights required. |
| Portable use | `Monitor-Hub-0.3.0-win64-portable.zip` | Extract and run `MonitorHub\bin\monitor_hub_qt.exe`. |
| Monitor Hub updater | `monitor-hub-windows-x64.zip` | Stable updater payload; intended for the built-in updater. |
| Integrity verification | `SHA256SUMS.txt` | SHA-256 checksums for the published assets. |

## What changed in 0.3.0

### Restored Qt parity and project Q&A

The current C++/Qt mainline now restores the project-specific adapter and question-answering capabilities that were still missing from the migrated desktop application.

Highlights:

- restored `markdown` and `qoi` adapters on the current C++ core;
- live checkpoint overrides and structured row metadata for QoI projects;
- portable per-user registry and Hub-data locations instead of author-machine fallback paths;
- persisted registry / Hub-data locations in desktop settings;
- first-run import path for an existing `monitor_hub_projects.json`;
- project-level read-only Q&A using Claude CLI;
- `qa_cwd`, `qa_sources`, `claude_config_dir`, and optional `live_query` support;
- live takeover JSONL/Markdown tail rendering inside the Qt desktop UI.

The project Q&A path remains read-only: it does not grant command, takeover, or recovery authority.

### Desktop resilience and lifecycle

The desktop application now has a more complete Windows lifecycle around the monitoring core.

Added or strengthened:

- rotating per-user application logs;
- log access from diagnostics, tray, and `Ctrl+Shift+L`;
- persisted window geometry, selected project, and selected tab;
- clean/unclean session markers and safe startup recovery notices;
- durable outbox -> desktop notification delivery without implicit acknowledgement;
- advisory network reachability state;
- bounded automatic-control retry with immediate refresh after recovery;
- deterministic local control remains available when the network is explicitly offline;
- About/diagnostics surfaces with application and Qt version information;
- desktop shortcuts including `F5`, `Ctrl+N`, `Ctrl+K`, `Alt+1..6`, `Ctrl+,`, `Ctrl+Shift+L`, `F1`, and `Ctrl+Q`;
- Qt runtime setup in Windows CI so packaged desktop tests execute reliably.

Network reachability is advisory only and never becomes project-health truth.

### Drag-and-drop and Recent Files

The Qt main window now accepts local file and folder drops with conservative behavior:

- drop a directory to open it or prefill a new monitoring request;
- drop `monitor_hub_projects.json` to import it after confirmation and configuration backup;
- common logs/documents/images can open through the system default application;
- unrecognized files are recorded in Recent Files but are not automatically executed;
- multiple dropped paths are collected safely rather than all being launched.

Recent Files keeps the 15 most recently opened local paths, deduplicates them, supports Unicode Windows paths, and exposes a quick menu with clear-history support.

### Global workspace search

The sidebar now has a visible search field and `Ctrl+F` shortcut.

Global search covers already-loaded normalized data:

- projects;
- task rows and row metadata;
- Issues;
- Protocol v1 events;
- Recent Files.

Search results deep-link to the matching project, task, Issue, event, or local file where possible.

Search does not parse raw logs into a second health model; normalized project/task/event state remains authoritative.

### Configuration backup and recovery

Desktop settings now support versioned JSON snapshots.

The release can:

- manually back up current desktop configuration;
- automatically snapshot configuration before real settings changes;
- keep the five most recent snapshots;
- restore a selected snapshot;
- create an undo snapshot before restore when possible.

Snapshots contain Monitor Hub-managed, non-secret desktop configuration only, such as close-to-tray, notifications, automatic control, runtime paths, launch-at-login state, and Recent Files.

Configuration recovery does **not** roll back project outputs, tasks, events, recovery state, scientific/business results, or workspaces.

### Event timeline improvements

The project Protocol v1 timeline is now significantly easier to navigate:

- free-text filtering across event type, display name, task, Issue, source, authority, summary, and evidence references;
- family filters for Issue, Agent, Task, Notification, Project, and Monitor events;
- current-task-only filtering;
- dedicated Issue column;
- event ID, correlation ID, and evidence details in tooltips;
- double-click local evidence when available;
- otherwise drill down to the associated task;
- global-search deep links can focus the matching event.

Filtering is presentation-only and never changes event projection or Issue lifecycle semantics.

## Compatibility and authority

0.3.0 is additive relative to 0.2.1:

- no Protocol v1 JSON schema break;
- no stable project/task/issue/event ID changes;
- no recovery-policy authority expansion;
- L1/L2/L3 decision boundaries remain unchanged;
- desktop notifications do not implicitly acknowledge durable outbox records;
- updater archive name, manifest format, and install layout remain compatible;
- project/workspace data remains outside the managed application payload.

## Upgrade from 0.2.1

0.2.1 users can upgrade directly to 0.3.0 through the stable updater or by installing the new Windows installer.

Project/workspace data, logs, local Hub runtime data, and scientific/business outputs are not part of the managed application payload and are not removed during upgrade or uninstall.

Development checkouts containing `.git` remain protected from self-overwrite; update source checkouts with Git rather than the release updater.
